# Local Defensive Plugin & Home Network Integration

The Spyware Accountability Framework (SAF) is designed to operate as a completely passive analysis and mapping engine. To respect this boundaries-first design and keep SAF lightweight, any active blocking or state modifications on a personal computer or local network are handled via a **clean handoff pattern**.

The **Local Defensive Integration Plugin** (`examples/local_defensive_plugin.py`) is an optional, self-contained companion tool. It allows individuals to securely bridge passive SAF analysis directly into their local home networks and computers.

---

## 🛑 Strict Boundaries

Before utilizing this plugin, please remember the following core rules:
1. **Local Defense Only:** This plugin only generates files or scripts to block traffic destined for *your own* computer or local network. Never attempt to use generated outputs to probe, query, or interfere with external/adversary systems.
2. **Review Firewall Scripts:** The generated `firewall_block.sh` contains platform-specific commands to block target IP addresses. **Always inspect and review this script** before executing it with `sudo`.

---

## Operational Mechanics

The plugin can consume actionable SAF reports in two different ways:

### Mode 1: Directory Watching (`watch` mode)
The plugin scans a directory on your machine (e.g., `/tmp/saf_reports`) for new JSON report files generated by SAF pipelines. When a new actionable report is detected, the plugin automatically parses and extracts Indicators of Compromise (IOCs).

```bash
python examples/local_defensive_plugin.py watch --watch-dir /tmp/saf_reports --output-dir ./local_defense
```

### Mode 2: Webhook Server (`server` mode)
The plugin starts a lightweight, local HTTP server (by default on `127.0.0.1:8080`) that acts as a webhook receiver. You can configure SAF pipelines to POST their actionable findings directly to this server:

```bash
python examples/local_defensive_plugin.py server --port 8080 --output-dir ./local_defense
```

To configure a SAF pipeline to forward reports to this server, use the `--webhook-url` argument:

```bash
python -m pipelines.network_forensics_pipeline \
  --input examples/synthetic_network_capture_description.md \
  --output /tmp/saf_report_output.json \
  --webhook-url http://127.0.0.1:8080/
```

## Generated Artifacts & How to Deploy Them

When an actionable report is processed, the plugin merges new IOCs into three unique defense files within your configured `--output-dir`.

### 1. Pi-hole / AdGuard Home Domain List (`pihole_blocklist.txt`)
Contains a plain list of malicious domains, formatted with one domain per line. This is fully compatible with popular home DNS sinkholes.

* **How to deploy to Pi-hole:**
  1. Copy the path to your generated `pihole_blocklist.txt` or host it on a local web server.
  2. Log into your Pi-hole admin dashboard.
  3. Navigate to **Adlists**.
  4. Paste the URL or absolute local file path (`file:///path/to/local_defense/pihole_blocklist.txt`) into the **Address** field.
  5. Click **Add** and run `pihole -g` in your Pi-hole terminal to update gravity.

### 2. Local Host File (`hosts_blocklist.txt`)
Contains standard `/etc/hosts` mapping templates (`0.0.0.0 malicious-domain.xyz`).

* **How to deploy:**
  1. Open the generated `hosts_blocklist.txt`.
  2. Append these lines to your operating system's hosts file:
     - **macOS/Linux:** `/etc/hosts` (requires `sudo`)
     - **Windows:** `C:\Windows\System32\drivers\etc\hosts` (requires Administrator privilege)
  3. Flush your DNS cache:
     - **macOS:** `sudo dscacheutil -flushcache; sudo killall -HUP mDNSResponder`
     - **Linux:** `sudo systemd-resolve --flush-caches`
     - **Windows:** `ipconfig /flushdns`

### 3. Local Firewall script (`firewall_block.sh`)
An executable shell script containing commands to block outbound connections to target malicious IP addresses.

* **How to deploy:**
  1. Open and review `firewall_block.sh` to ensure you agree with the target IP block rules.
  2. Run the script using your terminal:
     ```bash
     chmod +x local_defense/firewall_block.sh
     ./local_defense/firewall_block.sh
     ```
  3. The script detects and applies:
     - **Linux:** `iptables` DROP rules for the outbound IP addresses.
     - **macOS:** `pfctl` rules under an anchor named `com.apple/saf_block`.

## Benefits for Home Adoption
- **Zero External Dependencies:** No need to install complex enterprise agents or security software. Everything runs locally on your own computer.
- **Privacy-First:** Your local network data remains entirely private. Analysis is performed on-device or within your local perimeter, and generated block lists are compiled locally.
- **Easy Automation:** By setting up the local plugin to start on system boot (via `systemd` on Linux, `launchd` on macOS, or Task Scheduler on Windows), you can fully automate home threat intelligence updates.
